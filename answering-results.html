Models and mathematical definitions

The speech models still process audio internally. “Empty thinking” means no separate S2 reasoning or notes. Transcript-only readers may reason after the question arrives.

Notation

For one of the six evaluation cases, \(m\) identifies one of the five models below, and \(p_m(\cdot\mid\cdot)\) is that model’s conditional output distribution. \(x\) is the meeting history before the request, \(q\) is the request, and \(y\) is the model’s response. In S1, \(x\) and \(q\) are audio; \(y\) includes generated speech and any native response text. In text S2, \(x\) is a ground-truth or generated transcript, \(q\) is text, and \(y\) includes the final answer and any exposed request-time reasoning.

For earlier thinking, \(i\) indexes a note-generation call from 1 through \(K\), the number of calls made on chunks before the request. \(x_{\le i}\) is the transcript available through chunk \(i\), and \(g\) is the instruction to produce a summary or structured notes. \(z_i\) is the generated pre-thinking result for chunk \(i\), including any exposed reasoning text and the final summary or notes.

\(Z_{<i}\) is the ordered collection of valid saved summaries or notes from calls before \(i\); \(Z\) is the collection retained before the request. Only the final saved text is reused: earlier native reasoning text is counted but is not passed to later calls.

Each earlier call generates pre-thinking from the transcript so far, saved earlier results and the chosen instruction:

\[z_i\sim p_m(z_i\mid x_{\le i},Z_{<i},g)\]

For example, \(z_3\) is the pre-thinking generated after the third earlier chunk; if its saved summary or notes pass the format and source-ID checks, that saved text can enter \(Z\). These checks do not establish that its contents are correct. The actual request and reference answer are absent from earlier calls; the reference is also absent from the final reader input.

For the request, the duplex and transcript-only settings use \(p_m(y\mid x,q)\); the earlier-note settings use \(p_m(y\mid x,q,Z)\). T1/T2 use ground-truth transcripts; T3/T4 use generated transcripts. Summary and structured-note conditions use different instructions and saved results.

The Thinking reader exposes request-time reasoning; Instruct does not expose a native thinking channel. The duplex expression summarizes a native streaming loop over audio, not a single audio call. The common answer-format instruction and requester label are omitted.

2 · Noisy transcripts still support answering

With automatic speech recognition (ASR) and automatic speaker labels, reactive S2 produces 4–6 complete answers out of six. Across the six evaluated prefixes, lexical word error rate (WER)—word substitutions, deletions and insertions divided by reference words—is 32.9% for Parakeet and 32.5% for Whisper.

Speaker attribution remains imperfect; annotation-mapped conditions in the following figures use reference speaker identities and are diagnostic. The diarization model was trained on data including AMI.

3 · Earlier notes move work before the request

Reactive readers see the transcript when asked. The other conditions also receive summaries or structured notes saved before the question, without knowing that question. Each reader still receives the full transcript.

With the ground-truth transcript, structured notes preserve Thinking’s 6/6 complete answers and reduce mean request-time reasoning from 2,278 to 1,815 tokens. Two questions account for the reduction; the other four use more tokens. Instruct improves from 4/6 to 5/6 with structured notes.

With Whisper and automatic speakers, summaries raise Thinking from 4/6 to 5/6 and reduce mean request-time reasoning from 1,933 to 1,459 tokens. Outcomes vary by transcript and note format.

The ground-truth Thinking reader generates 14,254 tokens reactively versus 317,496 with structured notes, counting the earlier calls once per meeting and goal. This is 22.3× more total generated tokens; token count is a cost proxy, not measured latency or compute.

Saved notes are accumulated snapshots, and reference-mapped speaker labels can change across prefixes. The small sample supports case-level comparisons, not stable rankings.

How the executed S2 calls combine transcripts and saved notes

A transcript prefix is all transcript available before a cutoff; a chunk is the newly arrived segment. A note snapshot is one completed summary or structured-note JSON output. Each earlier call contains a system message and one user message with separate past_transcript and previous_results fields.

Per-meeting call layout (schematic):

Update 1: [system] [transcript: chunk 1] [earlier notes: none]
          → snapshot 1
Update 2: [system] [transcript: chunks 1 + 2] [snapshot 1]
          → snapshot 2
Update 3: [system] [transcript: chunks 1 + 2 + 3] [snapshots 1 + 2]
          → snapshot 3

Question: [answering system] [full available transcript]
          [all valid snapshots before the question] [question]
          → answer

Earlier snapshots are quoted as data inside the user message. The caller rebuilds this pair of messages for every call; it does not append each new chunk after the preceding notes as a continued sequence of user and model messages. vLLM prefix caching is enabled as a computation optimization.

Each structured snapshot can contain up to twelve notes. The caller appends a valid snapshot to the previous snapshots, so the accumulated input can exceed twelve entries. Outputs are checked for format and available source IDs; repeated facts are retained. Only the final summary or note JSON is reused. Earlier native reasoning text contributes to the token count but is absent from subsequent prompts.

How full-prefix diarization annotates only the newly saved words

Each update makes a new diarization call using the entire audio prefix from the meeting start. ASR processes the new chunk with up to two seconds of preceding audio. Word timestamps connect the ASR output to the speaker activity predicted for that prefix.

The annotation function first discards ASR words whose original midpoint is before the new chunk start, with a 0.0001 s numerical tolerance. It clips word ends to the chunk end and rejects invalid intervals. Words crossing the left boundary are assigned using their midpoint and can retain a start time just before the boundary. ASR alignment errors can still produce repeated or omitted boundary words.

For each retained word, the code selects the speaker with the greatest predicted activity overlap around its timestamp, using a 0.04 s margin. If there is no overlap, the label is unknown. If the two leading overlap amounts differ by less than 0.05 s and both are positive, the winning label is still assigned and an overlap_ambiguous flag is recorded. Consecutive words are then grouped into speaker-attributed segments. Only these new segments are appended; older saved segments remain in place.

Illustrative arrival order: Alice speaks at 5 s and Bob at 12 s in a first 0–30 s chunk. In the new 30–60 s chunk, Bob speaks at 35 s before Alice at 45 s. A second call on 0–60 s still encounters Alice at 5 s before Bob at 12 s, so it can retain Alice as Speaker0 and Bob as Speaker1. A call on only 30–60 s would encounter them in the opposite order. Our caller uses the full prefix. Sortformer assigns channels following speaker arrival order, as described in the NVIDIA model card.

How reference speaker identities are matched to predicted labels

AMI participant labels A–D identify the annotated participants. Predicted labels Speaker0–Speaker3 identify diarizer output channels. Their correspondence is estimated from the time overlap between predicted speaker activity and AMI annotated utterances within the available prefix. The code chooses a one-to-one assignment maximizing total overlap; any assigned pair with positive overlap is accepted, without an additional strong-confidence threshold.
