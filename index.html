Model architecture

DuplexOmni: listen, speak, and reason together.

A continuous speech interface pairs a fast interaction model with an asynchronous reasoning model. S1 keeps the conversation moving; S2 supplies deeper reasoning when requested.

Hear the reproductionsFollow the S1–S2 exchange

Two systems, different jobs

S1 / Interaction

Listen and respond continuously

S1 is the released DuplexOmni model, derived from Qwen3-Omni. Its audio encoder and Thinker consume each incoming slice, track conversation history, and produce transcription, speech text, and control fields. Talker turns the Thinker’s output into speech.

S2 / Reasoning

Work on a request in the background

S2 is a separate language model or agent. It receives text context from S1 and returns concise guidance. Our single-request reproduction uses Qwen3-4B-Thinking-2507. S1 can keep listening and speaking while this request is active.

Thinker belongs to S1. It is the interaction model’s internal language component. S2 is a separate backend with its own context and generation process.

The model from input to waveform

1 · Encode the next audio slice

The audio-only reproduction feeds mono audio in 480 ms slices. The audio encoder represents the incoming sound; each next Thinker request contains the new slice, retained interaction history, and any newly available S2 guidance. The full model also supports visual input.

2 · Decide what to say and do

The Thinker returns incremental user text (asr), assistant text (tts), speech control (tts_control), and reasoning control (system2_control). Its hidden representations also condition Talker, so speech generation uses the model’s internal features.

3 · Generate speech codes

Talker retains its own generation history. It predicts six 80 ms codec frames for each 480 ms slice. MTP, the multi-token predictor, supplies the remaining audio codebooks needed to represent each frame.

4 · Decode and play

Code2Wav converts speech codes into waveform samples. The local loop queues synthesis in order and drains playable audio in 20 ms packets. Incoming user audio continues on its own clock while the model speaks.

How S1 and S2 exchange information

S1 → S2

Context and a start signal

S1 accumulates recognized user text and assistant speech text. Its [THINK] control starts an asynchronous S2 request using the selected text context.

⇄
S2 → S1

A completed guidance clause

The controller collects a complete outward clause from S2’s streamed final content, removes the command delimiters, and queues its plain text for S1’s next from_s2 field.

  1. Collect context. The native path supplies the dialogue accumulated from S1’s actual transcription and assistant text. The model-triggered arithmetic reproduction uses the accumulated user transcription alone, with S2’s system instruction.
  2. Start reasoning. system2_control: "[THINK]" launches S2. The arithmetic example uses the model’s own signal; the human outlet example explicitly forces one dispatch.
  3. Keep S1 running. S2 runs in a background task. S1 continues processing 480 ms inputs and can produce acknowledgment or answer speech while waiting.
  4. Admit usable guidance. A complete clause, such as 391, enters a pending queue. Private reasoning tokens stay in S2; only the outward guidance is sent back to S1.
  5. Speak with the new information. The next S1 request includes the pending text in from_s2. S1 generates the response through its ordinary Thinker–Talker speech path.
